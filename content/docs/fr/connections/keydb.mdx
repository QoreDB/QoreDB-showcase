# KeyDB

Le driver **KeyDB** est inclus dans Core. Il utilise le protocole Redis, avec sa propre identité de connexion et ses limites fonctionnelles.

## Se connecter

1. Ouvrez **Nouvelle connexion** et choisissez **KeyDB**.
2. Renseignez l’hôte, le port (**6379** par défaut), les identifiants et la base ou le namespace.
3. Configurez TLS pour votre point d’accès, choisissez l’environnement et **testez la connexion** avant de l’enregistrer.

Choisissez KeyDB explicitement. QoreDB ne sonde pas le serveur pour le distinguer de Redis et n’accepte pas de schéma `keydb://`. Utilisez `rediss://` pour TLS.

```text
redis://USER:PASSWORD@HOST:6379/0
```

Remplacez les valeurs en majuscules par vos paramètres. Pour les moteurs compatibles, vérifiez le driver sélectionné après import d’une URL : le protocole seul peut n’identifier que le moteur parent.

## Capacités et limites

Le driver RESP existant permet d’explorer les clés et d’exécuter des commandes Redis. Le chemin de l’URL est un index de base, pas un nom de base SQL. Les limites du driver Redis s’appliquent ; l’administration propre à KeyDB n’est pas une fonctionnalité distincte de QoreDB.

## Dépannage

Si la connexion échoue, vérifiez le point d’accès, le port, les identifiants et les certificats. Si une commande reste indisponible après connexion, vérifiez les capacités du driver avant de modifier les permissions.
