# Serveur MCP

QoreDB v0.1.39 inclut `qore-mcp`, un serveur Model Context Protocol local pour les outils IA externes. Il partage le moteur, les connexions enregistrées et le coffre d’identifiants de QoreDB. L’accès MCP est inclus dans **Core** ; la fédération entre bases nécessite **Pro**.

## Activer l’accès

1. Ouvrez **Paramètres → Agents IA** dans QoreDB.
2. Autorisez explicitement chaque connexion à exposer. Les connexions existantes et nouvelles sont **masquées par défaut**.
3. Utilisez le chemin du binaire MCP détecté et la configuration proposée pour votre client. L’écran affiche également la version du binaire.
4. Redémarrez ou reconnectez votre client MCP, puis demandez-lui de lister les connexions disponibles.

Le binaire est livré avec l’application desktop et disponible dans les fichiers de la release. Le transport utilise **stdio** : le client lance le processus, sans port HTTP à ouvrir.

## Outils disponibles

| Outil | Fonction |
| --- | --- |
| `list_connections` | Lister uniquement les connexions explicitement exposées aux agents. |
| `list_namespaces` | Découvrir les bases et schémas. |
| `list_tables` | Lister les tables et collections. |
| `describe_table` | Inspecter les colonnes et clés. |
| `preview_table` | Prévisualiser un nombre limité de lignes. |
| `search_schema` | Rechercher des objets dans le schéma. |
| `run_query` | Exécuter une requête en lecture seule dans un namespace explicite. |
| `explain_query` | Examiner un plan de requête. |
| `list_saved_queries` | Découvrir les requêtes de la bibliothèque du workspace actif. |
| `run_saved_query` | Exécuter une requête enregistrée avec des variables validées. |
| `run_federated_query` | **Pro :** croiser les données des connexions exposées. |

Les ressources de schéma utilisent des URI `qore://`. Le serveur propose aussi les prompts `audit_table`, `explain_slow_query` et `document_schema`.

## Workspaces et requêtes enregistrées

Lancez le serveur depuis un projet contenant un workspace `.qoredb`, ou indiquez son répertoire :

```bash
/chemin/absolu/vers/qore-mcp --workspace /chemin/absolu/vers/projet
```

Les requêtes enregistrées proviennent de la bibliothèque de ce workspace. Les variables sont validées et substituées sous forme de littéraux typés. Sans workspace, les outils de requêtes enregistrées ne peuvent pas lire de bibliothèque.

Pour Claude Code, vous pouvez enregistrer directement le binaire :

```bash
claude mcp add qoredb -- /chemin/absolu/vers/qore-mcp --workspace /chemin/absolu/vers/projet
```

Pour compiler depuis les sources, exécutez cette commande à la racine du dépôt QoreDB :

```bash
cargo build --manifest-path src-tauri/Cargo.toml -p qore-mcp --release --features duckdb-bundled
```

`QOREDB_CONFIG_DIR` permet de choisir un répertoire de configuration différent.

## Contrôles d’accès

Les sessions restent en lecture seule. Les plafonds de lignes, délais, quotas et traces d’audit s’appliquent ; les sessions inactives sont fermées après dix minutes. Le masquage Pro s’applique aux données renvoyées. Les requêtes fédérées utilisent uniquement les connexions exposées ; le moteur DuckDB embarqué n’accède ni aux fichiers locaux, ni aux URL, ni aux extensions.

<Callout type="warning">
Lecture seule ne signifie pas confidentialité : un client IA externe peut transmettre les résultats à son fournisseur de modèle. Exposez uniquement les connexions appropriées, privilégiez des rôles restreints et configurez le masquage si nécessaire.
</Callout>
