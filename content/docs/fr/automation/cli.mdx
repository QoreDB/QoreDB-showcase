# Accès en ligne de commande

La CLI `qore` réutilise le moteur, les connexions enregistrées et le coffre d’identifiants de QoreDB. En v0.1.39, elle suit la même politique d’accès que le MCP : **les connexions doivent être explicitement exposées** et **chaque session CLI est en lecture seule**, même si la connexion desktop autorise les écritures.

## Autoriser une connexion

Dans l’application, ouvrez **Paramètres → Agents IA** et activez les connexions accessibles à la CLI. Les connexions nouvelles et existantes sont masquées par défaut. `qore connections` ne liste que les connexions exposées ; connaître l’identifiant d’une autre connexion ne donne pas accès à celle-ci.

Les plafonds de lignes, délais, quotas, traces d’audit et masques restent appliqués. La CLI sert aux scripts de lecture et d’inspection, pas aux scripts de migration ou de mutation.

## Commandes

```bash
qore connections
qore query CONNECTION_ID "SELECT 1"
qore tables CONNECTION_ID DATABASE --schema public
qore describe CONNECTION_ID DATABASE TABLE --schema public
```

Remplacez les valeurs en majuscules. L’option `--schema` est facultative et dépend du moteur. Utilisez les identifiants renvoyés par `qore connections`, pas un nom de connexion inventé.

Les résultats sont du JSON sur stdout. Les erreurs sont écrites sur stderr avec un code de sortie non nul. La syntaxe des requêtes dépend du moteur sélectionné.

## Choisir un workspace

La CLI détecte un workspace `.qoredb` depuis le répertoire courant ou accepte une option globale :

```bash
qore --workspace /chemin/absolu/vers/projet connections
qore --workspace /chemin/absolu/vers/projet query CONNECTION_ID "SELECT 1"
```

Un workspace explicite doit contenir un `.qoredb/workspace.json` valide, ou permettre de retrouver son projet parent ; un chemin invalide produit une erreur. Sans workspace, le coffre par défaut est utilisé.

`QOREDB_CONFIG_DIR` choisit un autre répertoire de configuration. Copier la configuration ne garantit pas à lui seul l’accès aux identifiants : le trousseau ou coffre nécessaire doit aussi être accessible dans l’environnement où la CLI s’exécute.

## Compiler depuis les sources

Depuis la racine du dépôt QoreDB :

```bash
cargo build --manifest-path src-tauri/Cargo.toml -p qore-cli --release
```

Le binaire est généré dans le répertoire cible du workspace Rust (`src-tauri/target/release/qore` avec la configuration par défaut).

## Dépannage

Une liste vide indique généralement que les connexions ne sont pas autorisées pour les agents, ou que la CLI lit un autre workspace ou une autre configuration. Une écriture est refusée volontairement ; désactiver la lecture seule de la connexion desktop n’autorise pas les écritures CLI.
