# Command-line access

The `qore` CLI reuses QoreDB’s engine, saved connections and credential vault. It follows the same access policy as MCP: **connections must be explicitly exposed**, and **every CLI session is read-only**, even if the desktop connection allows writes.

## Authorize a connection

In the desktop app, open **Settings → AI Agents** and enable the connections that the CLI may access. New and existing connections are hidden by default. `qore connections` only lists exposed connections; knowing another connection’s ID does not grant access.

The CLI retains row caps, timeouts, rate limits, audit logging and column masking. It is intended for read-only scripts and inspection, not migration or mutation scripts.

## Commands

```bash
qore connections
qore query CONNECTION_ID "SELECT 1"
qore tables CONNECTION_ID DATABASE --schema public
qore describe CONNECTION_ID DATABASE TABLE --schema public
```

Replace uppercase placeholders. The `--schema` option is optional and depends on the engine. Use the IDs returned by `qore connections`, not an invented connection name.

Results are JSON on stdout. Failures go to stderr and return a non-zero exit code. Query syntax follows the selected engine.

## Select a workspace

The CLI detects a `.qoredb` workspace from the current directory, or accepts a global option:

```bash
qore --workspace /absolute/path/to/project connections
qore --workspace /absolute/path/to/project query CONNECTION_ID "SELECT 1"
```

An explicit workspace must contain a valid `.qoredb/workspace.json` (or resolve to its parent project); an invalid path is an error. Without a workspace, the default vault is used.

`QOREDB_CONFIG_DIR` selects a different application configuration directory. A copied configuration alone does not guarantee access to credentials: the required keyring or vault access must also be available in the environment where the CLI runs.

## Build from source

From the QoreDB repository root:

```bash
cargo build --manifest-path src-tauri/Cargo.toml -p qore-cli --release
```

The binary is generated in the Rust workspace’s target directory (`src-tauri/target/release/qore` with the default configuration).

## Troubleshooting

An empty connection list usually means the connections have not been enabled for agent access or the CLI is reading a different workspace/configuration. A write query is refused by design; changing the desktop connection’s read-only flag will not enable CLI writes.
